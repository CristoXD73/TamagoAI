# Relay live test, 2026-10-01: Tamago really talking to Claude, Codex and ChatGPT

The owner asked: "trigger them to actually speak with Claude or Codex, I want to see what happens to those chats and
how well it will relay info."

**Setup.** The live gateway (`scripts/tamago-up.sh`, Gemma 4 12B) received typed messages over the same HTTP path the
phone uses, so they also appeared in the phone chat. The helpers were real: Claude Code 2.1.283 and codex-cli
0.157.1.

**Review.** A workflow had three independent agents look at the run: one tested the game, one compared each helper's
words with what Tamago passed on, and one audited the relay code. A skeptic then tried to refute each code finding;
23 of 23 held. Raw evidence:
- `/Volumes/Storage/AI/TamagoAI/relay/` (`tasks.json` and the three `2026-10-01-*.log` files)
- `logs/hands.log`
- `brain.sqlite` traces 63–74

## The game Codex built

The game is in `/Volumes/Storage/AI/relay/worktrees/sandbox/give-the-agario-terminal-swpk`, branch
`tamago/give-the-agario-terminal-swpk`. Run it from Terminal or iTerm2 at 80×24 or larger:

```sh
cd /Volumes/Storage/AI/relay/worktrees/sandbox/give-the-agario-terminal-swpk && python3 agario.py
```

It's genuinely Agar.io-like, and its 5 unit tests pass:
- pellets, 12 AI rivals, eat or be eaten (the 1.2× mass rule)
- bigger means slower, and a camera that follows you across a 100×50 world
- pause and restart

But it is **almost unplayable**. Across 200 simulated games, a player standing still is eaten in all 200 (median
1.4 s), and a perfect 4-direction fleeing bot is eaten in 197 (median 2.6 s). Rivals start chasing from 18 units
but can spawn 12 units away, and about 64 % of them start big enough to eat you. Codex's own smoke test printed
"Eaten! Final mass: 12", and it still reported the game as verified.

Other issues:
- an unknown escape sequence quits the game (for example ESC [ C arrows, or Alt-letter)
- keys only work in lowercase
- no splitting

## Findings

Live (K1–K8) and from the fidelity comparison (N1–N10):

| ID | Finding |
|---|---|
| K1 | The spoken confirmation drops "Say yes to go." when the owner's request has 2+ sentences (speech is capped at 2 sentences) |
| K2 | "Claude is on it" is said before the run can fail; failures and finishes are never announced (R3 not built); no automatic fallback (R4 not built) |
| K3 | Handing a task to another helper loses the original request |
| K4 / N5 | ChatGPT gets no DONE contract, so the relay keeps the last line, cut at 200 characters with markdown left in |
| K5 | "How are the helpers doing?" isn't routed to the hands, so the chat model invents a status |
| K6 / N9 | "What did ChatGPT say?" starts a new task (reworded) instead of reading the answer |
| K7 / N7 | Codex's stale "commit blocked" is passed on (and used as the commit message); the branch and run command are never told |
| K8 | "Agar.io" is split into two sentences when spoken |
| N1 | Codex's question was never spoken to the owner; in the meantime Tamago said "Codex is working on the code" |
| N2 | The usage numbers were 63 h stale ("14 % of the week left"; the reality was over 100 %). The fallback always picks Claude |
| N3 | It looks up usage before every task (3–4 s each) |
| N4 | Status shows the last 3 tasks of any age, so old tasks appear and a waiting question can be pushed out |
| N6 | K3 doubled Codex's time (3 m 41 s for about 1 m 55 s of work) and cost a question |
| N8 | The screen text and the voice disagree; the screen invented a "manual push" |
| N10 | Claude's failed task left an empty worktree and branch |

summary:

| ID | Sev. | Finding |

**Overall.** The plumbing works: real helpers run on their own branches, questions round-trip, and the relay
commits for Codex. But the information coming back to the owner is unreliable. Tamago says "on it" before failures,
loses briefs and answers, invents statuses, and never volunteers results or questions.

## Fixed (same day, Claude Opus 5.5 workflow implementer)

Every finding below was worked on in `Gateway/` (relay, hands, router, composer, orchestrator). The tests are in
`Gateway/test/relay-fidelity.test.js` (named by finding id) and `Gateway/test/relay.test.js`. Label for all of it:
**UNIT_TESTED_ONLY**. Fake agent processes, real git in temp folders, a scripted model. Nothing here has been run
against the real gateway, Gemma, Claude Code or Codex yet.

| ID | Status | What changed / why not fully |
|---|---|---|
| K1 | fixed | The composer always keeps a trailing "Say yes to go." and shortens the text in front of it. The confirmation quotes the request as one clause ("…runs on terminal, Agario like."). |
| K2 | partly | `relay_start` waits up to 5 s (`startWaitMs`) for an early ending. A limit or failure is said with its reason and reset time, and Tamago offers the other coding helper ("Give it to Codex? Say yes to go."). Every ending (question, done, unclear, failed, limited, interrupted) is volunteered on the owner's next interaction, by rule. **Not fixed:** nothing reaches the Watch until the owner talks to Tamago. That needs push (R3 APNs) or the `/v1/inbox` endpoint (a protocol change). The transfer is offered, not automatic (R4). |
| K3 | fixed | New `relay_handoff {agent}` tool, plus a rule for "give it to Codex instead". It sends the original request word for word with a baton: who had it, why it stopped, its commits, its open question. Uncommitted work is committed as WIP first. Work continues on the same branch and worktree. |
| K4 / N5 | fixed | ChatGPT and other read-only tasks get an answer contract (`ANSWER_RULES`). The full final message is stored (up to 2,000 characters). The summary is the DONE line, sentence-bounded and without markdown. The phone gets up to 1,500 characters, the Protocol V1 §18 long-answer cap, which wasn't changed. |
| K5 | fixed | "helpers" routes to the hands. Status phrasings with a helper's name go to `relay_status` by rule, with no model involved. |
| K6 / N9 | fixed | New `relay_result {agent?}` tool, plus a rule for "what did ChatGPT say/answer/build". The gist is spoken; the full answer is a long answer on the phone. The orchestrator stores it and `detail()` returns it without calling a model. When the model does call `relay_start`, a reworded task is replaced by the owner's own words. |
| K7 / N7 | fixed | Codex is told not to commit; the relay commits for it. The commit message is the task text plus the cleaned summary, with "commit blocked" clauses removed. Agents may add a `RUN: <command>` line, which is recorded and never executed. Status and result say what was built and the branch it's committed on; the run command goes on the screen and phone. |
| K8 | fixed | New sentence splitter (`src/brain/speech/text.js`): "Agar.io", "agario.py", "e.g.", "1.2" and "2.1.283" stay whole. |
| N1 | partly | A waiting question is spoken on the owner's next interaction ("Codex has a question: …"), and status lists it first. Without push, the owner still has to talk first (see K2). |
| N2 | partly | A `rejected` status or a window at 100 % or more, with a future reset, routes new coding work to Codex and says why ("Claude is out until Fri 12:00 PM."). An early limit is also caught at start (K2). **Not fixable here:** Claude's figures only update while Claude runs, so they can be old. Windows whose reset has passed are no longer shown as current. |
| N3 | fixed (prompt) | The prompt says never to call `helpers_usage` before giving work. The out-of-usage check reads the usage file directly, with no tool call. Not yet checked with the real model. |
| N4 | fixed | Status lists every running or waiting task (any age, with its age) first, then up to 3 tasks finished in the last 12 h. Older ones only appear on request (`include_older`). |
| N6 | fixed | Follows from K3. The time saved hasn't been measured live. |
| N8 | fixed | After `relay_status` / `relay_result`, the tools' own words are the reply (spoken and on screen), not the model's retelling. The prompt also forbids inventing next steps. |
| N10 | fixed (revised) | A limited, failed, stopped or interrupted run with no commits from a known base, nothing just committed and a clean worktree has its worktree and empty branch removed (review SM1, SM2, G3). |
| F1 | fixed | A reply goes to a waiting helper only if it is plausibly the answer. Forbidden, forget, off-the-record, thanks and greetings never qualify, and neither do Mac commands or new-task phrasings. A question the owner hasn't heard yet takes only an option or an addressed reply ("Codex: …"). |
| F2 | fixed (revised) | Replies ending in "?" or opening with a wh-word or is/are/can/could/did/does/"do you" count as questions (review G2). "Do it with curses" and "Have it start small" are answers. |
| F3 | fixed | Build words don't stop an answer ("Build the game here") unless it is clearly a new task ("tell Claude to…", "a new app…"). |
| F4 | fixed | A pending confirmation is answered only by a short, plain "no". "No, build here" drops it and goes to the helper. |
| F5 | fixed | With several questions waiting, the reply goes to the one it names ("tell Codex …", "Codex: …") or whose option it matches. Otherwise Tamago asks "For Claude or Codex?", or by task when one helper has several (review SM9). |
| F6 | fixed | `relay_stop {agent}` stops that helper's task. The confirmation names the helper and the task. |
| F7 | fixed | The safety net proposes only for requests ("can you build…", imperatives), never for questions. Status questions are handled by rule before the model. |
| F8 | fixed | Endings are read from the whole final message with markdown and indentation removed; the last ASK_OWNER/DONE wins. "unclear" is its own state. |
| F9 | fixed | `rejected` or 100 % comes first: "Claude is out until <day time>". Reset times include the weekday when they aren't today, and past windows are dropped. |
| F10 | fixed (revised) | Status lists every waiting task, any age. Unaddressed replies reach a question for 12 h after the owner last *heard* it; after that, options and addressed replies only (review G2). |
| F11 | fixed | The reset time is kept from the stream (`resetsAt`, "limit reached\|epoch", "resets Oct 2 at 12pm") and spoken. |
| F12 | fixed | Summaries are cut at sentences, without markdown (see K4). |
| F13 | fixed | See N4. |
| F14 | fixed (revised) | When the gateway starts (`recover`, never the CLI or evals), `running` tasks whose owning process is gone become `interrupted`, which releases the project lock. Leftovers are committed or empty worktrees removed, and the owner is told (review SM7). |
| F15 | fixed | Worktrees branch from `main` when it exists, else HEAD, or from `base` per project in `projects.json` (`{ "path": …, "base": … }`). `base` / `baseSha` are recorded. |
| F16 | fixed | Every ending commits leftover changes as WIP on the task branch (stopped and timed-out runs included). |
| F17 | fixed | Codex's rules say "Do not commit: the relay commits". |
| F18 | fixed (UNVERIFIED CLI) | `codex exec --json -s <sandbox> --skip-git-repo-check resume <id> <msg>`. That flag order wasn't run against codex-cli (rule: don't run codex in tests). Check it on the first real resume. |
| F19 | fixed | Naming a helper isn't an offer; the model must actually offer. Build work never goes to ChatGPT, whether through the safety net, the model's own `relay_start`, or a handoff. |
| F20 | fixed | One `normalizeAgent()` for both the confirmation and the run ("chat gpt" → ChatGPT in both). |
| F21 | fixed | A run is `limited` only if it ends without DONE/ASK_OWNER after a rejected status or a limit error. A later `allowed` event clears it. |
| F22 | fixed (revised) | A send/pay/install inside what is built doesn't trip its guardrail ("build my app's email feature", "a script that sends an email"); in its own clause it stays forbidden (review G4). Delete and secret always apply. |
| F23 | fixed | A one-line reply keeps its leading number. Underscores stay on screen ("say_hello") and are spoken as spaces. |

## Review of the fixes (same day, Claude Opus 5.5 workflow implementer)

Reviewers checked the uncommitted fixes above and raised 30 problems (state: SM1–SM9, truth: R1–R11, safety:
G1–G10). Each was checked against the code; all were real. Tests: the "review" section of
`Gateway/test/relay-fidelity.test.js`, one test per id (fakes, real git in temp folders). Still **UNIT_TESTED_ONLY**.

| ID | Status | What changed |
|---|---|---|
| SM1 / G3 | fixed | `tidy()` counts commits from `baseSha`, else the merge-base with the recorded or project base branch, never `HEAD..HEAD`. An unknown base means an unknown count and no removal. A handoff passes the worked-out base on. |
| SM2 | fixed | Removal needs nothing just committed, no failed commit (index.lock, pre-commit hook) and a clean `git status` after the commit attempt. |
| SM3 / R2 / G1 | fixed | Stop and handoff phrasings are never forwarded to a waiting helper (unless the reply is exactly an option); the stop/handoff rule handles them, waiting tasks included. |
| SM4 | fixed | Options match as whole words; short ones ("Yes", "No", "Go") only at the start of the reply. |

| SM7 | fixed | F14 recovery runs only with `recover: true` (the gateway's `loadConfig`), and skips tasks whose recorded `owner` pid is alive (within the 30-min watchdog). `brain-gateway.test.js` no longer builds a relay on the real state dir. |

**Still open after the review:** child processes a helper started (npm test, python3) can outlive its SIGTERM/SIGKILL
(no process-group kill yet). Pid-based ownership can be fooled by pid reuse inside the 30-minute window. G8's prose
limit is a heuristic: an unquoted pasted DONE line followed by a few lines still counts.

**Not in scope, still true:** the game Codex built is almost unplayable (see above). That's a new task for a helper,
not a relay bug.
