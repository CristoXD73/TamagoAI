# Relay live test, 2026-10-01: Tamago really talking to Claude, Codex and ChatGPT

The owner asked: "trigger them to actually speak with Claude or Codex, I want to see what happens to those chats and
how well it will relay info."

**Setup.** The live gateway (`scripts/tamago-up.sh`, Gemma 4 12B) received typed messages over the same HTTP path the
phone uses, so they also appeared in the phone chat. The helpers were real: Claude Code 2.1.283 and codex-cli
0.157.1.

**Review.** A workflow had three independent agents look at the run: one tested the game, one compared each helper's
words with what Tamago passed on, and one audited the relay code. A skeptic then tried to refute each code finding;
23 of 23 held. Raw evidence:
- `/Volumes/Storage/AI/TamagoAI/relay/` (`tasks.json` and the three `2026-10-01-*.log` files)
- `logs/hands.log`
- `brain.sqlite` traces 63–74

## The game Codex built

The game is in `/Volumes/Storage/AI/relay/worktrees/sandbox/give-the-agario-terminal-swpk`, branch
`tamago/give-the-agario-terminal-swpk`. Run it from Terminal or iTerm2 at 80×24 or larger:

```sh
cd /Volumes/Storage/AI/relay/worktrees/sandbox/give-the-agario-terminal-swpk && python3 agario.py
```

It's genuinely Agar.io-like, and its 5 unit tests pass:
- pellets, 12 AI rivals, eat or be eaten (the 1.2× mass rule)
- bigger means slower, and a camera that follows you across a 100×50 world
- pause and restart

But it is **almost unplayable**. Across 200 simulated games, a player standing still is eaten in all 200 (median
1.4 s), and a perfect 4-direction fleeing bot is eaten in 197 (median 2.6 s). Rivals start chasing from 18 units
but can spawn 12 units away, and about 64 % of them start big enough to eat you. Codex's own smoke test printed
"Eaten! Final mass: 12", and it still reported the game as verified.

Other issues:
- an unknown escape sequence quits the game (for example ESC [ C arrows, or Alt-letter)
- keys only work in lowercase
- no splitting

## Findings

Live (K1–K8) and from the fidelity comparison (N1–N10):

| ID | Finding |
|---|---|
| K1 | The spoken confirmation drops "Say yes to go." when the owner's request has 2+ sentences (speech is capped at 2 sentences) |
| K2 | "Claude is on it" is said before the run can fail; failures and finishes are never announced (R3 not built); no automatic fallback (R4 not built) |
| K3 | Handing a task to another helper loses the original request |
| K4 / N5 | ChatGPT gets no DONE contract, so the relay keeps the last line, cut at 200 characters with markdown left in |
| K5 | "How are the helpers doing?" isn't routed to the hands, so the chat model invents a status |
| K6 / N9 | "What did ChatGPT say?" starts a new task (reworded) instead of reading the answer |
| K7 / N7 | Codex's stale "commit blocked" is passed on (and used as the commit message); the branch and run command are never told |
| K8 | "Agar.io" is split into two sentences when spoken |
| N1 | Codex's question was never spoken to the owner; in the meantime Tamago said "Codex is working on the code" |
| N2 | The usage numbers were 63 h stale ("14 % of the week left"; the reality was over 100 %). The fallback always picks Claude |
| N3 | It looks up usage before every task (3–4 s each) |
| N4 | Status shows the last 3 tasks of any age, so old tasks appear and a waiting question can be pushed out |
| N6 | K3 doubled Codex's time (3 m 41 s for about 1 m 55 s of work) and cost a question |
| N8 | The screen text and the voice disagree; the screen invented a "manual push" |
| N10 | Claude's failed task left an empty worktree and branch |

Code audit, confirmed by skeptics (severity after verification). The full text is in the workflow transcript;
summary:

| ID | Sev. | Finding |

**Overall.** The plumbing works: real helpers run on their own branches, questions round-trip, and the relay
commits for Codex. But the information coming back to the owner is unreliable. Tamago says "on it" before failures,
loses briefs and answers, invents statuses, and never volunteers results or questions.
